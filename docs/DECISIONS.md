- 2026-11-22 — Stack chosen as in .claude/skills/onlinedars-stack (spec left stack to the team) — to be confirmed with the client.
- 2026-11-22 — Pinned major lines: Next.js 15.5, React 19.2, NestJS 11, Prisma 6.19, TypeScript 5.9, zod 4, Vitest 3, ESLint 9 (flat config). Newer majors exist (Next 16, Nest 12, Prisma 7, TS 7) but the skill specifies Next 15 / Nest 11; Prisma 7 changes client generation and TS 7 is the new native compiler — not worth the risk for v1. Revisit after launch.
- 2026-11-22 — Vitest + `unplugin-swc` for API tests (SWC emits decorator metadata that Nest DI needs); `@nestjs/cli` (`nest build`) for API builds. Output `dist/main.js` (api) and `dist/worker.js` (worker).
- 2026-11-22 — Config: own zod schema (`apps/api/src/config/env.ts`) instead of `@nestjs/config`; `.env` loaded with Node's `process.loadEnvFile`. Prisma CLI scripts use `dotenv-cli` to read the root `.env` (no-op in CI where vars are set).
- 2026-11-22 — Added `@nestjs/throttler` (minor dep): 20 req/min/IP on auth endpoints, disabled in tests.
- 2026-11-22 — Global guards: `JwtAuthGuard` then `RolesGuard` on every route (deny by default, `@Public()` to opt out). The guard re-reads the session + user on each request (one PK lookup) so logout, password reset and disabling a user take effect immediately and the role always comes from the DB.
- 2026-11-22 — Refresh tokens: opaque `<sessionId>.<secret>`, one `Session` row per device, HMAC-SHA256 (key `JWT_REFRESH_SECRET`) of the current secret stored, rotated on each refresh with a compare-and-swap. Presenting a non-current secret ⇒ session revoked (`REFRESH_TOKEN_REUSED`). Trade-off: two tabs refreshing at the exact same moment can log the user out; the web client should serialise refresh calls.
- 2026-11-22 — Cookie `od_refresh`: httpOnly, SameSite=Lax, Secure in production, Path `/api/v1/auth`. The web proxies `/api/v1/*` to the API (Next rewrite in dev, Caddy in prod), so the browser talks same-origin and `NEXT_PUBLIC_API_URL=/api/v1`.
- 2026-11-22 — Phone sign-up requires an SMS OTP (purpose REGISTER); email sign-up has no verification yet (email provider pending). Forgot-password sends the OTP to the account's phone and always answers 202 (no account enumeration). OTP: 6 digits, 5 min, 5 attempts, 60 s resend cooldown, only HMAC stored.
- 2026-11-22 — Extra models beyond the skill list: `OtpCode` (SMS codes) and `Notification` (in-app notifications for backend-payments). `ExamQuestion` is the exam's own question pool (not linked to practice questions, so practice results never reveal exam answers); its options reuse `QuestionOption` via a nullable `examQuestionId` with a CHECK that exactly one owner is set.
- 2026-11-22 — 4×6 rule enforced in the DB as well as services: triggers in migration `0001_init` reject a 5th practice per lesson / 7th question per practice, and reject `Lesson.isPublished = true` unless 4×6 is complete. No unique index on `position`, so reordering is free. Also CHECKs on price/amount ≥ 0, free course price = 0, user has email or phone.
- 2026-11-22 — Money: `Int` tiyin (max ≈ 21 million so'm per course/order), `currency` default `UZS`. Switch to BigInt only if prices ever exceed that.
- 2026-11-22 — Orders reuse the `PaymentStatus` enum (PENDING/PAID/CANCELLED/FAILED/REFUNDED) and have a sequential `number` for providers/receipts besides the cuid `id`.
- 2026-11-22 — Certificates: `publicId` (unique) is the ID printed on the PDF and used in `/verify/{publicId}`; holder name and course title are snapshotted at issue time.
- 2026-11-22 — Web: shadcn/ui components written by hand from the new-york v4 sources (no CLI run); `components.json` is present so `pnpm dlx shadcn add …` works later. next-intl runs without locale routing (single `uz` locale). `output: 'standalone'` is on except on Windows, where pnpm symlinks need Developer Mode (`NEXT_STANDALONE=1` forces it); Docker/CI build on Linux.
- 2026-11-22 — Sentry is wired for the API only (`@sentry/nestjs`, init only if `SENTRY_DSN`); web Sentry to be added with the frontend work.
- 2026-11-22 — (devops) Web and API share one origin: Caddy routes `/api/*` to the api container, the rest to web; `NEXT_PUBLIC_API_URL=/api/v1` is baked into the web image, server-side calls use `API_URL=http://api:4000/api/v1` — one web image works for staging and production, auth cookies stay first-party. Files are served from a separate `FILES_DOMAIN` (MinIO behind Caddy) so presigned URLs work; the api must sign against `S3_PUBLIC_URL`.
- 2026-11-22 — (devops) Three images in GHCR: `onlinedars-web`, `onlinedars-api`, `onlinedars-worker`. The worker is a second target of `infra/docker/api.Dockerfile` (api + apt Chromium + fonts) so the api image stays small; Puppeteer must launch `/usr/bin/chromium` (`PUPPETEER_EXECUTABLE_PATH`) with `--no-sandbox --disable-dev-shm-usage` since it runs as the non-root `node` user without a setuid sandbox.
- 2026-11-22 — (devops) Image tags: full commit sha (+ `main`) on main; on `v*` tags the tagged commit is rebuilt (GHA layer cache makes it near-identical) and tagged `:<sha>`, `:vX.Y.Z`, `:vX.Y`. Simpler than retagging across workflow runs.
- 2026-11-22 — (devops) Deploy jobs are gated on repository **variables** `STAGING_HOST` / `PRODUCTION_HOST` (not secrets), because the `secrets` context can't be used in a job-level `if` and environment secrets only exist inside a job that already targets the environment (which, for production, would trigger the approval just to check). Missing SSH/ENV secrets inside an enabled environment fail the job with a clear message.
- 2026-11-22 — (devops) Server login to GHCR uses the deploy run's short-lived `GITHUB_TOKEN` (`packages: read`), no long-lived PAT; `docker logout` after pulling. Rollbacks on the server use locally cached images.
- 2026-11-22 — (devops) Migrations run as a one-shot `migrate` compose service (api image, `prisma migrate deploy`) before `up -d`; the api image carries a global Prisma CLI pinned to the installed `@prisma/client` version. Rollbacks never run migrations (expand → migrate → contract).
- 2026-11-22 — (devops) pnpm version comes only from `packageManager` in the root `package.json` (CI's `pnpm/action-setup` reads it; Dockerfiles pin `PNPM_VERSION=9.15.9` — keep in sync).
- 2026-11-22 — (devops) MinIO stopped publishing community Docker images in late 2025. Prod compose pins the last release we rely on (`MINIO_IMAGE` override). Before production, decide: keep self-hosted MinIO (build from source), switch to another S3-compatible server, or use the hosting provider's S3 (preferred if it is in Uzbekistan).
- 2026-11-22 — (devops) Docker could not be installed on the dev PC overnight, so Dockerfiles were not built locally; CI's "Docker image" jobs build them on every PR and are the first real check.
- 2026-11-23 — (devops) The CI "Dependency audit" job is informational: it always passes, writes `pnpm audit --prod --audit-level=high` output to the job summary and raises a warning annotation. Findings are triaged weekly with Dependabot (see `docs/USER_ACTIONS.md`), not by blocking unrelated PRs.
- 2026-11-23 — (devops) Docker builds use `pnpm turbo run build --filter=@onlinedars/<app>` so `packages/shared` (whose `dist/` is not in the build context) is built first via `dependsOn: ["^build"]`.

- 2026-11-23 — (backend-payments) Providers see `Order.number` (Payme `account.order_id`, Click `merchant_trans_id`); Click `merchant_prepare_id`/`merchant_confirm_id` = order number too, so no schema change was needed. Provider callbacks lock the order row (`SELECT … FOR UPDATE`) and change status with conditional `updateMany`, so concurrent/duplicate callbacks grant enrollment exactly once.
- 2026-11-23 — (backend-payments) Payme error mapping: -31050 order not found, -31051 order not payable (paid/cancelled/expired or student already enrolled), -31099 another open transaction on the order. Cancel before perform keeps the order PENDING (student can retry); cancel after perform = refund. Errors returned after a write (e.g. timeout-cancel then -31008) commit that write.
- 2026-11-23 — (backend-payments) Click repeated Complete for a paid transaction answers -4 "Already paid" (Click's documented answer) rather than repeating 0; enrollment is not repeated either way. A Click Prepare is refused (-9) while a Payme transaction is open on the same order, and Payme Create is refused (-31099) while any transaction is open, to avoid double charging.
- 2026-11-23 — (backend-payments) Refunds follow the `REFUND_POLICY` setting (`revoke` default | `keep`), read directly from the `Setting` table (key owned by settings; backend-content may expose it in the admin settings API).
- 2026-11-23 — (backend-payments) Added `bullmq` (^5.34, part of the agreed stack) for the `payment-recheck` worker job. When `REDIS_URL` is absent from the raw environment the worker falls back to an in-process interval (the config schema defaults REDIS_URL, so the raw env is checked). Provider status lookups sit behind `PaymentStatusChecker` (default answers UNKNOWN; no provider API is called).
- 2026-11-23 — (backend-payments) In-app notifications store Uzbek fallback `title`/`body` plus `type` + `data`; the web should render i18n text from `type`/`data`. Email/SMS channels are interfaces with no-op defaults.
- 2026-11-23 — (backend-payments) Payment unit tests use an in-memory fake Prisma (`modules/payments/testing/payments-fake-db.ts`) wired to the real services; row locks, constraints and HTTP are covered by `apps/api/test/payments.e2e-spec.ts` in CI.

- 2026-11-23 — (backend-learning) Grading is all-or-nothing per question (full `points` or 0); multi-select needs exactly the correct set. FILL_BLANK / MATCHING text is normalised: NFC, Uzbek apostrophe variants (ʻ ‘ ’ `´) →`'`, trimmed, whitespace collapsed, lower-cased. Unanswered = wrong; answers to foreign question ids are ignored.
- 2026-11-23 — (backend-learning) Lesson complete = material viewed + every _required_ practice passed (percent ≥ `Practice.passScore`; 0 = any submission). Completion is sticky (`LessonProgress.completedAt`). Sequential unlock: a lesson opens when every earlier **required** lesson is complete (optional lessons never block). Course % = completed required / required lessons (all lessons if none required). Only published lessons count.
- 2026-11-23 — (backend-learning) Exam: questions drawn per attempt from the exam's own pool (`shuffleQuestions` → random subset, else first N by position; a smaller pool yields the whole pool). Timing is server-side: submit accepted until `expiresAt + 30 s` (`EXAM_SUBMIT_GRACE_SECONDS`), later → 409 `EXAM_TIME_OVER` and the attempt is closed as EXPIRED **graded from its autosaved answers** (so it may still pass). Overdue attempts are expired lazily on the next request (no cron). Concurrent starts are serialised with `pg_advisory_xact_lock`; submit closes the attempt with a compare-and-swap on status. No retake after a pass (`EXAM_ALREADY_PASSED`). Exam results show per-question correctness only — never the correct answers or explanations (the pool is reused across attempts); practices do show them.
- 2026-11-23 — (backend-learning) Certificates: issued once per (user, course) — the DB unique index decides races; a loser gets the existing row. `publicId` = `OD-XXXX-XXXX-XXXX` (Crockford base32, 60 random bits, retry on collision); verify normalises input. Issuing sets `Enrollment.completedAt` and creates a `CERTIFICATE_ISSUED` Notification row. Template priority: course template → default template → built-in (`apps/api/src/templates/certificate/default-template.ts`); placeholder values are HTML-escaped.
- 2026-11-23 — (backend-learning) PDF pipeline behind interfaces: `PdfRenderer` (Puppeteer impl), `CertificateStorage` (S3 impl), `CertificatePdfQueue` (BullMQ or inline). Inline mode is chosen when the **raw** `REDIS_URL` env var is unset/empty (AppConfig gives it a localhost default, so the config value can't tell). Missing PDF on download → re-enqueue + 409 `CERTIFICATE_PDF_PENDING`.
- 2026-11-23 — (backend-learning) New deps in apps/api: `bullmq` (queues; ioredis comes with it — connection built from the URL, no direct ioredis dep), `puppeteer-core` (not `puppeteer`: no Chromium download; uses `PUPPETEER_EXECUTABLE_PATH`, args `--no-sandbox --disable-dev-shm-usage` per devops), `@aws-sdk/client-s3` (certificate PDFs; to be replaced by backend-content's StorageService adapter when it merges).
- 2026-11-23 — (backend-learning) Admin students (`/admin/students*`, ADMIN only) live in a new `students` module; grant/revoke access writes `AuditLog` rows directly via Prisma (actions `ENROLLMENT_GRANTED` / `ENROLLMENT_REVOKED`, before/after snapshot). Revoking keeps progress and certificates.
- 2026-11-23 — (backend-learning) Reports use Asia/Tashkent calendar days (UTC+5, no DST); activity uses `$queryRaw` with `date_trunc`-style `to_char` grouping (table/column names are constants, never user input). Ranges default to the last 30 days, clamped to 366.

- 2026-11-23 — (backend-content) Public catalog shows only `PUBLISHED` courses and, inside them, only published lessons (modules without published lessons are hidden). `HIDDEN` and `ARCHIVED` courses are not public at all (`GET /courses/:slug` → 404); enrolled students keep access through backend-learning's `/me/*` routes.
- 2026-11-23 — (backend-content) Course publish rule: `POST /admin/courses/:id/status {PUBLISHED}` needs ≥1 lesson and **every** lesson published (409 `COURSE_INCOMPLETE`). The check runs only on the transition; a new draft lesson added later simply stays invisible. New courses are always `DRAFT`.
- 2026-11-23 — (backend-content) 4×6: services check the counts in a transaction (409 `LESSON_PRACTICE_LIMIT` / `PRACTICE_QUESTION_LIMIT` / `LESSON_INCOMPLETE` with the counters in `details`); trigger errors from 0001_init are mapped to the same codes (409) for races. Deleting a practice/question of a published lesson unpublishes the lesson in the same transaction and the DELETE returns `{ deleted: true, lessonUnpublished }` (200) so the admin UI can tell the user. Moving practices/questions between parents is not supported.
- 2026-11-23 — (backend-content) Course delete only when it has no enrollments, orders or certificates (409 `COURSE_NOT_DELETABLE`, archive instead). Lessons/modules delete with cascade (incl. student progress) — admin UI should confirm.
- 2026-11-23 — (backend-content) PATCH bodies are built with `toPatchSchema()` (packages/shared): all fields optional and create-defaults removed, so omitted fields are never reset. Question PATCH with `options` replaces all options; the merged question/material is re-validated with the create schema.
- 2026-11-23 — (backend-content) All list endpoints (also unpaginated child lists) return `{ items, total, page, pageSize }` per docs/api/ROUTES.md. Added beyond the contract: `GET /admin/{directions,teachers,faq}/:id`, `GET /admin/questions/:id`, reorder for materials/practices/questions (`PATCH …/reorder {ids}`), `GET /settings/public`, `GET /files/:year/:month/:name` (local storage only).
- 2026-11-23 — (backend-content) Storage: `StorageService` interface with S3 (hand-written SigV4 PUT/GET/DELETE via `fetch`, path-style for MinIO; verified against the AWS reference signature), local disk and memory drivers — no AWS SDK dependency for three calls. Driver: `STORAGE_DRIVER`, else S3 when `S3_ENDPOINT` is set, memory under tests, else local disk. Uploaded objects are addressed by an unguessable key and read via `S3_PUBLIC_URL` (needs a public-read policy on the `uploads/` prefix — see USER_ACTIONS). Limits: images ≤5 MB (jpeg/png/webp/gif — no SVG), files ≤50 MB (pdf, Office, zip, txt, csv); magic bytes must match the declared type.
- 2026-11-23 — (backend-content) Lesson TEXT HTML is cleaned server-side with a small regex backstop (`sanitize.ts`: scripts/iframes/styles, `on*=` handlers, `javascript:`/`data:` URLs). It is not a full sanitiser — the web must render lesson HTML through DOMPurify (or similar).
- 2026-11-23 — (backend-content) Settings are typed keys (`platformSettingsSchema`: platformName, tagline, contacts, logo, maintenanceMode, orderTtlMinutes, refundPolicy) stored one row per key, defaults in code; ADMIN-only PATCH writes an `AuditLog` row (`settings.update`, before/after) in the same transaction. `SettingsService.get(key)` is exported for other modules.

- 2026-11-23 — (frontend-admin) Admin pages are thin Server Components that render client feature components; all admin data is fetched client-side with TanStack Query through `src/lib/api/admin/*` (wrapping `apiFetch`). The access token is in memory only, so server components can't call admin endpoints; this also lets Playwright mock the API with `page.route`.
- 2026-11-23 — (frontend-admin) No new UI/editor dependencies: drag-reorder uses native HTML5 DnD plus keyboard (grip + ↑/↓, Alt+↑/↓, up/down buttons) instead of dnd-kit; rich text is a small contentEditable + `execCommand` editor instead of TipTap (output HTML must be sanitised by the API); selects/checkboxes are native elements styled like shadcn. Revisit (TipTap, dnd-kit) if editors need more.
- 2026-11-23 — (frontend-admin) Dev deps added: `@testing-library/{react,dom,user-event,jest-dom}`, `jsdom` (apps/web) for component tests (specs opt in with `// @vitest-environment jsdom`; vitest config gained `esbuild.jsx = automatic` and `vitest.setup.ts`), and `@playwright/test` at the root (CI runs `pnpm exec playwright`). Minimal `e2e/playwright.config.ts` starts only the web app (`next start` in CI).
- 2026-11-23 — (frontend-admin) Completeness response is normalised client-side: accepts both the brief's `{practices, required, questionsPerPractice[], ready}` and the shared `lessonCompletenessSchema` `{practicesRequired, isComplete, questionsPerPractice[{practiceId,questions,required}]}`. The publish button follows the server's `ready`/`isComplete` flag only.
- 2026-11-23 — (frontend-admin) Certificate template preview renders in `<iframe sandbox="">` (no scripts) with `{{fullName}}`, `{{courseTitle}}`, `{{issueDate}}`, `{{certificateId}}`, `{{verifyUrl}}`, `{{backgroundImageUrl}}` placeholders (values HTML-escaped). backend-learning's PDF renderer must use the same placeholder names.

- 2026-11-23 — (frontend-student) Cabinet pages are thin Server Components rendering client feature components; data is fetched in the browser with TanStack Query because the access token only lives in browser memory. Student calls go through a pluggable transport (`lib/api/student-fetch.ts`, `configureStudentAuth`) so the cabinet doesn't depend on the parallel auth layer; wire `authFetch` after merge.
- 2026-11-23 — (frontend-student) Cabinet-wide screens (dashboard, my courses, results, certificates list, payments, notifications) live in `src/features/cabinet/` (`features/certificate` and `features/course` belong to frontend-public). Student layout in `src/components/layout/student/`.
- 2026-11-23 — (frontend-student) Lesson TEXT materials: rendered as HTML if it looks like HTML, otherwise through a small built-in markdown subset; always sanitised again in the browser with DOMPurify (new minor dep `dompurify`). Videos: YouTube → `youtube-nocookie.com` embed, Vimeo → player embed, anything else → `<video>`. Only http(s) URLs are rendered.
- 2026-11-23 — (frontend-student) "Material viewed": explicit button plus auto-mark when the end of the material scrolls into view after at least 5 s on the page (endpoint is idempotent).
- 2026-11-23 — (frontend-student) Exam timer uses the server deadline corrected by `serverTime` (device clock skew doesn't matter); auto-submits once at 0 (immediately if the deadline already passed on load). Answers autosave to `localStorage` key `od.exam.<attemptId>` (all access in try/catch, cleared after submit); on resume local answers win over the server's `savedAnswers`. On `EXAM_TIME_OVER` / `EXAM_ATTEMPT_CLOSED` the UI returns to the status view.
- 2026-11-23 — (frontend-student) MATCHING is click-to-pair (left item → target; buttons with `aria-pressed`, keyboard accessible) plus HTML5 drag-and-drop of targets onto left items; each target can be used once. Exam results show only per-question correctness; practice results show the correct answers + explanations returned by the server after submit.
- 2026-11-23 — (frontend-student) Testing: Vitest projects `unit` (node) and `dom` (jsdom + Testing Library). Playwright at the root (`@playwright/test` root devDep, `e2e/playwright.config.ts`); cabinet specs mock the API with `page.route` and run at 375 px and 1280 px.

- 2026-11-23 — (frontend-public) Web auth: access token **in memory only**; on page load it is recovered with `POST /auth/refresh` (httpOnly cookie). Refresh is single-flight per tab and serialised across tabs with the Web Locks API (`navigator.locks`), so two tabs never present the same refresh secret (which the API treats as reuse and revokes). `authFetch` retries once after a refresh on 401; 403 is never retried.
- 2026-11-23 — (frontend-public) Middleware uses a non-sensitive `od_role` cookie (role name only, Path=/, SameSite=Lax, 30 days, not httpOnly) set by the web on login/refresh and cleared on logout or a rejected refresh. UX hint only: forging it shows an empty shell because the API checks every request. Visitors without it are treated as anonymous without calling `/auth/refresh`. Middleware runs only on `/cabinet`, `/admin`, `/checkout`; `/login` is not redirected by middleware (avoids loops with a stale hint) — the login form redirects client-side when a session exists.
- 2026-11-23 — (frontend-public) Public pages are Server Components rendered per request with API fetches cached 60 s (`next.revalidate`); static prerendering would bake in "API unavailable" states because the API isn't reachable during `next build`. Certificate verification is never cached. If the API is down, pages render an error/empty state.
- 2026-11-23 — (frontend-public) Catalog filters are a plain GET form (works without JS); state lives in the URL (`?search=&directionId=&price=free|paid&page=`). FAQ and course program use native `<details>` (no accordion dependency). Descriptions/bios render as plain text, never HTML.
- 2026-11-23 — (frontend-public) Checkout sends only `{courseId, provider}` and follows `redirectUrl` only if it is https (http only for localhost). The provider return (`/checkout/{courseId}?orderId=`, also `/checkout/result?orderId=`) polls `GET /orders/:orderId` every 2 s for up to 2 min and ignores provider URL params. 401/403/404 stop polling; network/5xx errors are retried.
- 2026-11-23 — (frontend-public) Test-only dev dependencies: `jsdom`, `@testing-library/{react,dom,user-event,jest-dom}` (apps/web) and `@playwright/test` (root, because CI runs `pnpm exec playwright` from the root). Component specs opt into jsdom with `// @vitest-environment jsdom`.
- 2026-11-23 — (frontend-public) Auth forms use `method="post"` so a submit before hydration can never put the password in the URL.
