# Architecture decisions

<!-- date — decision — why -->

- 2026-11-22 — Stack chosen as in .claude/skills/onlinedars-stack (spec left stack to the team) — to be confirmed with the client.
- 2026-11-22 — Pinned major lines: Next.js 15.5, React 19.2, NestJS 11, Prisma 6.19, TypeScript 5.9, zod 4, Vitest 3, ESLint 9 (flat config). Newer majors exist (Next 16, Nest 12, Prisma 7, TS 7) but the skill specifies Next 15 / Nest 11; Prisma 7 changes client generation and TS 7 is the new native compiler — not worth the risk for v1. Revisit after launch.
- 2026-11-22 — Vitest + `unplugin-swc` for API tests (SWC emits decorator metadata that Nest DI needs); `@nestjs/cli` (`nest build`) for API builds. Output `dist/main.js` (api) and `dist/worker.js` (worker).
- 2026-11-22 — Config: own zod schema (`apps/api/src/config/env.ts`) instead of `@nestjs/config`; `.env` loaded with Node's `process.loadEnvFile`. Prisma CLI scripts use `dotenv-cli` to read the root `.env` (no-op in CI where vars are set).
- 2026-11-22 — Added `@nestjs/throttler` (minor dep): 20 req/min/IP on auth endpoints, disabled in tests.
- 2026-11-22 — Global guards: `JwtAuthGuard` then `RolesGuard` on every route (deny by default, `@Public()` to opt out). The guard re-reads the session + user on each request (one PK lookup) so logout, password reset and disabling a user take effect immediately and the role always comes from the DB.
- 2026-11-22 — Refresh tokens: opaque `<sessionId>.<secret>`, one `Session` row per device, HMAC-SHA256 (key `JWT_REFRESH_SECRET`) of the current secret stored, rotated on each refresh with a compare-and-swap. Presenting a non-current secret ⇒ session revoked (`REFRESH_TOKEN_REUSED`). Trade-off: two tabs refreshing at the exact same moment can log the user out; the web client should serialise refresh calls.
- 2026-11-22 — Cookie `od_refresh`: httpOnly, SameSite=Lax, Secure in production, Path `/api/v1/auth`. The web proxies `/api/v1/*` to the API (Next rewrite in dev, Caddy in prod), so the browser talks same-origin and `NEXT_PUBLIC_API_URL=/api/v1`.
- 2026-11-22 — Phone sign-up requires an SMS OTP (purpose REGISTER); email sign-up has no verification yet (email provider pending). Forgot-password sends the OTP to the account's phone and always answers 202 (no account enumeration). OTP: 6 digits, 5 min, 5 attempts, 60 s resend cooldown, only HMAC stored.
- 2026-11-22 — Extra models beyond the skill list: `OtpCode` (SMS codes) and `Notification` (in-app notifications for backend-payments). `ExamQuestion` is the exam's own question pool (not linked to practice questions, so practice results never reveal exam answers); its options reuse `QuestionOption` via a nullable `examQuestionId` with a CHECK that exactly one owner is set.
- 2026-11-22 — 4×6 rule enforced in the DB as well as services: triggers in migration `0001_init` reject a 5th practice per lesson / 7th question per practice, and reject `Lesson.isPublished = true` unless 4×6 is complete. No unique index on `position`, so reordering is free. Also CHECKs on price/amount ≥ 0, free course price = 0, user has email or phone.
- 2026-11-22 — Money: `Int` tiyin (max ≈ 21 million so'm per course/order), `currency` default `UZS`. Switch to BigInt only if prices ever exceed that.
- 2026-11-22 — Orders reuse the `PaymentStatus` enum (PENDING/PAID/CANCELLED/FAILED/REFUNDED) and have a sequential `number` for providers/receipts besides the cuid `id`.
- 2026-11-22 — Certificates: `publicId` (unique) is the ID printed on the PDF and used in `/verify/{publicId}`; holder name and course title are snapshotted at issue time.
- 2026-11-22 — Web: shadcn/ui components written by hand from the new-york v4 sources (no CLI run); `components.json` is present so `pnpm dlx shadcn add …` works later. next-intl runs without locale routing (single `uz` locale). `output: 'standalone'` is on except on Windows, where pnpm symlinks need Developer Mode (`NEXT_STANDALONE=1` forces it); Docker/CI build on Linux.
- 2026-11-22 — Sentry is wired for the API only (`@sentry/nestjs`, init only if `SENTRY_DSN`); web Sentry to be added with the frontend work.
- 2026-11-22 — (devops) Web and API share one origin: Caddy routes `/api/*` to the api container, the rest to web; `NEXT_PUBLIC_API_URL=/api/v1` is baked into the web image, server-side calls use `API_URL=http://api:4000/api/v1` — one web image works for staging and production, auth cookies stay first-party. Files are served from a separate `FILES_DOMAIN` (MinIO behind Caddy) so presigned URLs work; the api must sign against `S3_PUBLIC_URL`.
- 2026-11-22 — (devops) Three images in GHCR: `onlinedars-web`, `onlinedars-api`, `onlinedars-worker`. The worker is a second target of `infra/docker/api.Dockerfile` (api + apt Chromium + fonts) so the api image stays small; Puppeteer must launch `/usr/bin/chromium` (`PUPPETEER_EXECUTABLE_PATH`) with `--no-sandbox --disable-dev-shm-usage` since it runs as the non-root `node` user without a setuid sandbox.
- 2026-11-22 — (devops) Image tags: full commit sha (+ `main`) on main; on `v*` tags the tagged commit is rebuilt (GHA layer cache makes it near-identical) and tagged `:<sha>`, `:vX.Y.Z`, `:vX.Y`. Simpler than retagging across workflow runs.
- 2026-11-22 — (devops) Deploy jobs are gated on repository **variables** `STAGING_HOST` / `PRODUCTION_HOST` (not secrets), because the `secrets` context can't be used in a job-level `if` and environment secrets only exist inside a job that already targets the environment (which, for production, would trigger the approval just to check). Missing SSH/ENV secrets inside an enabled environment fail the job with a clear message.
- 2026-11-22 — (devops) Server login to GHCR uses the deploy run's short-lived `GITHUB_TOKEN` (`packages: read`), no long-lived PAT; `docker logout` after pulling. Rollbacks on the server use locally cached images.
- 2026-11-22 — (devops) Migrations run as a one-shot `migrate` compose service (api image, `prisma migrate deploy`) before `up -d`; the api image carries a global Prisma CLI pinned to the installed `@prisma/client` version. Rollbacks never run migrations (expand → migrate → contract).
- 2026-11-22 — (devops) pnpm version comes only from `packageManager` in the root `package.json` (CI's `pnpm/action-setup` reads it; Dockerfiles pin `PNPM_VERSION=9.15.9` — keep in sync).
- 2026-11-22 — (devops) MinIO stopped publishing community Docker images in late 2025. Prod compose pins the last release we rely on (`MINIO_IMAGE` override). Before production, decide: keep self-hosted MinIO (build from source), switch to another S3-compatible server, or use the hosting provider's S3 (preferred if it is in Uzbekistan).
- 2026-11-22 — (devops) Docker could not be installed on the dev PC overnight, so Dockerfiles were not built locally; CI's "Docker image" jobs build them on every PR and are the first real check.
- 2026-11-23 — (frontend-public) Web auth: access token **in memory only**; on page load it is recovered with `POST /auth/refresh` (httpOnly cookie). Refresh is single-flight per tab and serialised across tabs with the Web Locks API (`navigator.locks`), so two tabs never present the same refresh secret (which the API treats as reuse and revokes). `authFetch` retries once after a refresh on 401; 403 is never retried.
- 2026-11-23 — (frontend-public) Middleware uses a non-sensitive `od_role` cookie (role name only, Path=/, SameSite=Lax, 30 days, not httpOnly) set by the web on login/refresh and cleared on logout or a rejected refresh. UX hint only: forging it shows an empty shell because the API checks every request. Visitors without it are treated as anonymous without calling `/auth/refresh`. Middleware runs only on `/cabinet`, `/admin`, `/checkout`; `/login` is not redirected by middleware (avoids loops with a stale hint) — the login form redirects client-side when a session exists.
- 2026-11-23 — (frontend-public) Public pages are Server Components rendered per request with API fetches cached 60 s (`next.revalidate`); static prerendering would bake in "API unavailable" states because the API isn't reachable during `next build`. Certificate verification is never cached. If the API is down, pages render an error/empty state.
- 2026-11-23 — (frontend-public) Catalog filters are a plain GET form (works without JS); state lives in the URL (`?search=&directionId=&price=free|paid&page=`). FAQ and course program use native `<details>` (no accordion dependency). Descriptions/bios render as plain text, never HTML.
- 2026-11-23 — (frontend-public) Checkout sends only `{courseId, provider}` and follows `redirectUrl` only if it is https (http only for localhost). The provider return (`/checkout/{courseId}?orderId=`, also `/checkout/result?orderId=`) polls `GET /orders/:orderId` every 2 s for up to 2 min and ignores provider URL params. 401/403/404 stop polling; network/5xx errors are retried.
- 2026-11-23 — (frontend-public) Test-only dev dependencies: `jsdom`, `@testing-library/{react,dom,user-event,jest-dom}` (apps/web) and `@playwright/test` (root, because CI runs `pnpm exec playwright` from the root). Component specs opt into jsdom with `// @vitest-environment jsdom`.
- 2026-11-23 — (frontend-public) Auth forms use `method="post"` so a submit before hydration can never put the password in the URL.
